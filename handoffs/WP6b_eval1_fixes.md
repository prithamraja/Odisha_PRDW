### T2 — Finding 1: the subject an officer names must bind, or the bot must not answer

**Cause, verified.** `_FOCUS_AREA_ALIASES` already maps "road construction" and "road works" to Roads. The alias never ran because the LLM extractor returned no `focus_area` for "road construction activities" on 10 of 11 phrasings, and the validator only aliases what the extractor hands it. "Swachh Bharat" and "piped water" bound because the extractor happened to emit a value.

**Fix, two parts.**

a) **Alias prefill.** Promote the categorical alias tables to a deterministic prefill beside the `$date_range` and amount prefills: scan the normalised question for alias keys of the slots the template offers (`focus_area` first; `status`, `scheme`, `theme`, `plan_type` where their tables exist), longest match wins, whitespace-collapsed, word-bounded. A prefilled slot leaves `askable`, the extractor remains the fallback, and the existing disagreement log records where the two differ — the same promotion path WP-5 T1 used, for the same reason: a reader with a narrow vocabulary that is right when it fires beats a model that sometimes returns nothing.

b) **Unbound-subject guard.** After extraction and prefill, if the question contains an alias key for a slot the template offers and that slot is still unbound, the answer is not served. Clarify with the alias's value as the chip ("Did you mean the Roads focus area?"), reason `unbound_subject`. This is the general rule finding 1 is one instance of: a question that names a subject must never be answered as if it had not.

**Prove.** Replay rows 303-313 bind `focus_area = Roads` and return the road count (not 400 for 2024-25). Rows 17-22, 215-227, 230-242 unchanged. Unit tests for the prefill on every alias key, and for the guard with the extractor stubbed to return nothing.

### T3 — Finding 2: the subject wins the comparison, the years combine

`comparison_breakdown` returns the first list-valued slot in extractor order. Change the rule: **a list on a non-year dimension takes the breakdown; the year list is used only when no other list exists.** When a year list is thereby combined, the echo names it: "(2024-2025 and 2025-2026 combined)", reusing the existing "(the values combined)" path. The phrase reader still overrides — "year-wise" in the question keeps the year breakdown.

**Prove.** Rows 42 and 44 return exactly two rows, Drinking water and Sanitation, each summed over the two years, and their sum equals the two single-year calls. A question saying "year-wise, water and sanitation" still groups by year. The T4 proof (EXP-009 two scalar calls) still holds.

### T4 — Finding 3: a count of nothing is 0, not "No records matched"

The WP-6 GROUPING SETS fix covers the 112 plain-total statements. It cannot cover a Count template that groups by the filtered column (STS-003 groups by `status_label`, so a status filter that matches nothing yields no rows) or one with a year breakdown over no rows (PLN-014 rows 246/257).

Handle it at render time, for `question_type == "Count"` (105 templates): an empty frame renders as one row with 0 in the count column, named from the statement's select list via `column_metadata`, and the echo unchanged. The "No records matched" sentence stays for Listing, Ranking and Lookup types, where an empty answer is the answer. The template's caveat still appends.

**Prove.** Rows 19, 246, 257 answer 0 with the echo. A Listing template with no rows still says no records. The 21 templates that legitimately return no rows in the Test Report keep their oracle counts (the oracle counts frame rows; assert the synthesised row is a render artefact, not a frame row).
