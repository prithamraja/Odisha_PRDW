## 2. Tasks

### T1 — Threshold replies: read the figure, respect the direction, ask in plain words

**a) Read the reply in three steps** (`pending_resolver.resolve_pending_reply`, numeric slot types only — `threshold`, `amount_threshold`, `top_n`):

1. **Deterministic.** Run `router.amount_from_text` over the reply, then a plain-number fallback (`\d[\d,]*(?:\.\d+)?` with an optional `%`) for the non-money readings of `$threshold`. Read a **direction word** alongside it: above / over / more than / at least / exceeding / ≥ → `above`; under / below / less than / up to / at most / within → `below`; none → `None`. Strip nothing else; the figure still goes through `parse_amount` and `_check_numeric_range` exactly as a typed number does today.
2. **Model fallback, only when step 1 finds no figure.** One call to the extractor model (`gpt-5.4-mini`, through `entity_extractor`'s client and `llm_usage` metering) with a single job: return `{"amount": "<figure with its unit word, copied as written>", "direction": "above" | "below" | null}` or `null`. It copies, never converts, never invents; a null re-asks. Its output goes through the same `parse_amount`, so a bad reading fails loudly rather than binding. Expected on wordy replies only ("twenty thousand", "two and a half lakh", "half a crore", Odia number words).
3. **Compare the direction to the template's.** `derive_catalog.py` derives, for each of the 15 threshold slots, the **direction** from the slot's own SQL operator (`>=` / `>` → `above`; `<` / `<=` → `below`) and the **unit** from its SQL context (a cost column → `rupees`; `100.0 * … /` → `percent`; `CURRENT_DATE` arithmetic → `days`; `COUNT(*)` → `activities`), and writes both on the slot declaration; `--check` pins them. **Derived, not migrated: no SQL text changes.** At resume: reply direction matches or is absent → bind and answer. Reply direction contradicts → **do not bind**; clarify (reason `direction_mismatch`): *"This question lists activities **above** a planned cost. Did you mean above ₹2 lakh, or do you want the ones below ₹2 lakh?"* Chip 1 resumes the paused question with the figure. Chip 2 routes as a new question — the original text with the direction phrase swapped — and if no template answers it, the ordinary no-match path says so. **The SQL operator is never flipped at runtime.**

**b) The ask itself.** Replace "For which amount threshold?" / "For which threshold?" with a sentence in the slot's own unit, from the derived `unit` and `direction`: rupees → *"Above what planned cost? For example ₹50,000 or 1 lakh."* (or "Below what cost?"); percent → *"Below what percentage?"*; days → *"How many days?"*; activities → *"At least how many activities?"*. Offer three example chips per unit (₹50,000 / 1 lakh / 5 lakh; 25% / 50% / 75%; 30 / 60 / 90 days; 5 / 10 / 20). A chip sends a bare figure and resumes through the pending path — `main.py`'s resume block must admit a `from_chip` reply for a numeric pending (today only `bool(pending.candidates)` gets that exception).

**c) Never lose the paused question on a wordy reply.** `_unusable_reply`'s `_RETRY_MAX_WORDS = 3` fall-through is what turns the second wordy reply into a new question. For numeric pendings: any reply that contains a figure resumes (step a); a reply with no figure re-asks with the unit sentence and the chips; only a reply with **no digit and no number word** and more than six words falls through. The `retried` one-shot stays as is for categorical pendings.

**Prove (offline, model stubbed).** Fixture of ~24 replies on EXP-033 (`>=`, rupees) and PLU-006 (`<`, rupees), plus one percent (ALR-011) and one days (ALR-008) case: the 8 bare forms answer as today; "above ₹20,000", "activities above 20,000", "more than 20,000 rupees", "the threshold is 20000", "20,000 and above" resume and answer with `amount_threshold = 20000`; "under 2 lakhs" on EXP-033 and "above 2 lakh" on PLU-006 produce `direction_mismatch` with two chips and never a served answer; "twenty thousand", "two and a half lakh" reach the stubbed fallback and bind what it returns; "hello there how are you today" falls through. `derive_catalog.py --check` pins direction and unit on all 15 threshold slots (`above`: EXP-033, IMP-013, IMP-009, IMP-019, IMP-020, ALR-001, ALR-008; `below`: PLN-045, PLN-069, PLU-006, PLU-009, ALR-011, DSS-001, DSS-005; ALR-003 read by hand, pinned).

### T2 — Fund split by scheme: a scheme is never a tied/untied value

Three layers, all deterministic, in `_fill_slots_or_clarify` / `_extract_slot_values`:

1. **Re-home.** A `$tied_untied` value that fails validation but validates as a `scheme` (exact or alias — "SFC", "Own Funds", "CFC", "15th FC") moves to the `$scheme` slot when the template offers one (every universal-filter template does), merging into any list already there. Logged as `rehomed tied_untied→scheme`. Runs before any clarification is raised.
2. **A list of schemes on a tied/untied statement is a per-scheme comparison.** When `$scheme` ends up list-valued on a template whose statement splits `tied_untied` (BUD-003, BUD-005, EXP-008, FND-001), apply the WP-6 T4 rule: bind the list **and** set the breakdown to `scheme` (`SLOT_TO_GROUP["scheme"]`), so "split the sanctioned funds into SFC and Own Funds" returns one row per scheme, not the tied/untied table filtered to two schemes. Echo: "(broken down by scheme)". The `unbound_subject` guard must then see `scheme` as bound and not ask "which scheme?".
3. **The vocabulary guard, for `$tied_untied` only.** A `$tied_untied` value from the extractor whose vocabulary (a registry value or an `_TIED_UNTIED_ALIASES` key — "tied", "untied", "basic grant", …) does not appear in the question is dropped and logged, never asked about. Build it table-driven (slot type → vocabulary), so D34.4's plan-type guard can reuse it later, but **wire only `tied_untied` here**. With layers 1 and 3 in place the "Tied / Untied / Other" chip set is reachable only when the officer actually wrote a tied/untied word that failed to resolve.

**Prove (offline, extractor stubbed).** On BUD-005: `{"tied_untied": "Own Funds"}` answers with `scheme = Own Funds`, no clarify; `{"tied_untied": ["SFC", "Own Funds"]}` answers with two scheme rows and the echo; `{"scheme": ["SFC", "Own Funds"]}` on BUD-002 unchanged; `{"tied_untied": "Tied"}` on a question that says "tied" still binds; `{"tied_untied": "Tied"}` on a question with no tied/untied word is dropped and logged. Gold #1423 still answers; #1402 / #1522 ("tied and untied") still answer the split with no scheme breakdown.
